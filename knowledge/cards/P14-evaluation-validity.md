# P14 — Evaluate appeal, usefulness and performance separately

**Type:** RESEARCH  — **Source IDs:** R6, R7, R8, E5, A2, S3

## Use when
An A/B test or design review risks turning model judgment into apparent objective proof.

## Evidence and scope
Evaluation design must match the actual construct measured; distinguish descriptive improvement from causal attribution. Refer to `knowledge/sources.json` for original source URLs and access limits.

## Transferable reasoning moves
1. Define constructs first: perceived visual quality, task effectiveness/efficiency, satisfaction, error behavior and accessibility.
2. Choose evidence collection suitable to each construct: screenshots, runtime checks, representative task tests, real-user questionnaires.
3. Blind judges to design-generation conditions and normalize viewports.
4. Report sample size, mean/spread, limitation and disagreement; do not infer significance from n=3.

## Do not infer
- Aesthetic attractiveness does not automatically improve objective task success.
- A single expert/LLM rating is not a validated user-preference instrument.

## Verify the output
Include negative results, untested assertions, and which comparisons are merely exploratory.
